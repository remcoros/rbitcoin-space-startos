# Updating upstream

1. Check https://github.com/smolcars/rbitcoin-space/releases for a stable release and review its node compatibility, configuration, storage migrations, and security changes.
2. Verify `ghcr.io/smolcars/rbitcoin-space:<version>` exists and includes linux/amd64 and linux/arm64 with `docker manifest inspect`. Confirm its revision label matches the release commit.
3. Update `images.explorer.source.dockerTag` in `startos/manifest/index.ts` and the version and translated release notes in `startos/versions/current.ts`. Keep real migrations with the version that introduced them.
4. Recheck rbitcoin's exported `ports`, `apis`, and `indexes` actions, its host IDs, `main` volume, and `datadir/rpc.cookie` contract; update the declared dependency range when compatibility changes. The Git dependency tracks `remcoros/rbitcoin-startos#main`; the lockfile records the exact commit. Recheck upstream's six network variables, entrypoint, data paths, uid, trusted-proxy settings, and `/readyz` fields.
5. Check the latest SDK with `npm view @start9labs/start-sdk version`, update the exact pin and lockfile if needed, then run `npm_config_allow_git=all make x86` and `npm_config_allow_git=all make arm`. The command-scoped npm setting permits the provider's transitive Git dependencies under the local npm policy.
6. When installation testing is authorized, verify node discovery, cookie rotation, required configuration prompts and re-arming, preservation of unrelated node settings, client rate-limit isolation through the StartOS proxy, WebSocket updates, and failure/recovery of the Esplora, storage, and address-index checks. Exercise address pages, transaction broadcast, Lightning and MCP toggling, restart persistence, and backup/restore. Do not call a build runtime validation.
